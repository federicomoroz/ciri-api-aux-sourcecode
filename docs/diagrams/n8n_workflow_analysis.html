Agente de contracargos
el circuito completo

Orquestación explícita en n8n. 36 pasos que se ejecutan siempre en el mismo orden, más 4 salidas de error — 40 nodos ejecutables, 46 con las notas del canvas. No hay un nodo de agente decidiendo qué herramienta llamar: por eso cada investigación es reproducible y auditable. Tocá cualquier nodo para ver qué hace y cómo se conecta.

Las rutas de la API se muestran sin el prefijo /api que comparten; /health y el webhook cuelgan de la raíz. El detalle completo de cada nodo está a un clic.

El modo demo no cambia este circuito. Los mismos 36 pasos, en el mismo orden: lo único que cambia es qué modelo contestan Sintetizar Resolución y Juez de Calidad — uno de free tier en vez de Claude. Sólo si no hay ningún free tier configurado esos dos pasos sirven el análisis ya calculado en vez de correr.

01–04

La URL de la API se resuelve una sola vez, en «Validar Formato TXN», y los quince nodos HTTP la leen de ahí: body del webhook, variable de n8n, o la API pública por defecto. Por eso el workflow se importa y corre sin configurar nada.

05–17

Un acierto de caché devuelve el informe ya generado y saltea todo lo demás: dos segundos en lugar de ciento trece. Cuando hay que investigar, acá se unen el RAG y la base de datos: Qdrant aporta qué políticas aplican y qué se hizo en casos parecidos, SQLite aporta los hechos exactos. Ningún umbral de negocio vive en el canvas — los límites de SLA, el ratio de contracargos y las reglas de reincidencia se le piden a la API, que los lee de domain/constants.py.

18–25

El código decide, el LLM explica: nueve de los trece campos de la resolución los calcula Python y sobrescriben siempre lo que devuelve el modelo. Después un segundo modelo puntúa esa resolución sobre cinco criterios con rúbricas.

26–36

Si el Juez puntuó 8.0 o más, el caso se reindexa como precedente en Qdrant. Cada investigación que sale bien mejora a la siguiente.
